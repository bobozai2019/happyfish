# 游戏状态机与信号契约

状态：`frozen`（Gate 1，2026-08-08）

Owner：T02/T05

## 1. 单局状态机

状态枚举：

- `RUNNING`：允许输入、生成、移动、射击和结算。
- `PAUSED`：暂停游戏树中玩法节点；暂停 UI 仍可响应。
- `RESULTS`：停止生成和射击，展示双方统计，只允许重开。

合法转换：

```text
RUNNING → PAUSED
PAUSED → RUNNING
RUNNING → RESULTS
RESULTS → RUNNING  # 创建全新局内状态
```

禁止 `PAUSED → RESULTS`；先恢复或由状态机内部原子转换。

## 2. 核心信号

| 信号 | 参数 | 发出者 | 消费者 | 时机 |
|---|---|---|---|---|
| `shot_fired` | `player_id:int, cannon_level:int, cost:int` | Cannon | Session/HUD/Audio | 扣费和实例化成功后 |
| `net_resolved` | `player_id:int, eligible_count:int, captured_ids:Array[StringName], total_reward:int` | CaptureService | Session/HUD | 网内判定全部完成后 |
| `fish_captured` | `player_id:int, fish_id:StringName, reward:int, world_position:Vector2` | CaptureService | Session/VFX/Audio | 单鱼原子归属成功后 |
| `coins_changed` | `player_id:int, old_value:int, new_value:int` | Session | HUD | 金币写入后 |
| `player_exhausted` | `player_id:int` | Session | HUD | 第二次真正耗尽后 |
| `boss_warning_started` | 无 | SpawnDirector | HUD/Audio | Boss 出现前 2 秒 |
| `boss_spawned` | 无 | SpawnDirector | HUD/Audio | Boss 进入场景时 |
| `session_state_changed` | `old_state:int, new_state:int` | Session | UI/Spawn/Input | 合法转换完成后 |

信号参数不得传入可被消费者修改的共享运行对象；需要集合时传复制后的 typed Array。

## 3. 发射与待结算

1. 仅 `RUNNING` 状态允许发射。
2. 若当前档位不可支付，自动选择玩家可支付的最高档位；若 1× 也不可支付，则拒绝发射。
3. 成功发射顺序固定为：选择档位 → 扣金币 → `pending_resolution_count += 1` → 实例化子弹 → 发出 `shot_fired`。
4. 子弹命中第一条鱼时在命中点生成渔网并停止；飞出有效边界时视为无鱼网结算。
5. 无论命中、出界或异常回收，每次成功发射最终必须且只能使 pending 减一。

## 4. 捕获算法

1. 渔网以炮台配置半径查询所有仍处于 `capturable` 状态的鱼。
2. 查询结果按鱼实例创建序号稳定排序，避免物理查询顺序造成平台差异。
3. 最终概率为 `clamp(base_chance * cannon_probability_multiplier + pity_bonus, 0.01, 0.80)`。
4. 每条鱼使用同一局内 `RandomNumberGenerator` 顺序独立判定。
5. 捕获采用鱼实例上的原子 `try_claim_capture(player_id)`；成功声明后其他渔网不得再次奖励。
6. `eligible_count == 0` 时不改变保底。
7. 有候选但最终捕获数为 0 时，增加该玩家 `empty_net_streak`。
8. 任意捕获成功时，将该玩家 streak 重置为 0。
9. streak 达 3 时 pity 为 0.05；达 5 时为 0.10；达 7 时先保证最低奖励的非 Boss 候选，其余候选继续正常判定。
10. 若 streak 达 7 但候选只有 Boss，不保证捕获，只使用 0.10 加成。

发布构建随机种子来自运行时；自动测试必须允许注入固定种子。

## 5. 金币、救援与结果

1. 捕获成功后，奖励只加给声明捕获的玩家，并更新数量、总价值和最大鱼。
2. 金币不得小于 0。
3. 金币为 0 但 `pending_resolution_count > 0` 时，不触发救援或耗尽。
4. 玩家第一次达到金币 0 且 pending 为 0 时：设置 `rescue_used = true`，增加 30 金币，继续游戏。
5. 玩家第二次达到金币 0 且 pending 为 0 时：设置 `is_exhausted = true`，停止该玩家输入。
6. 两名玩家都 exhausted 且全局无待结算射击时进入 `RESULTS`。
7. 结果只展示双方统计，不计算或显示胜者。
8. 重开必须销毁所有运行时鱼、子弹、渔网、定时器和玩家状态，再从默认资源创建新局。

## 6. Boss 调度

1. `elapsed_time >= 60s` 或合计捕获数 `>= 18` 时触发首次警告，二者取先到者。
2. 警告 2 秒后，若仍为 `RUNNING` 且没有 Boss，则生成鲸鲨 Boss；暂停时计时停止。
3. Boss 被捕获或离场后开始 90 秒冷却，冷却完成才允许再次警告。
4. 场上最多存在 1 个 Boss。

## 7. 失败模式

- 找不到资源：开发构建立即报错并停止 Gate 验收，不使用静默默认值。
- 子弹异常销毁：必须通过统一清理入口归还 pending。
- 同帧多网命中：原子声明保证单次奖励。
- UI 消费信号失败：不得阻止玩法状态更新，错误写入日志。
