# 单局规则契约

文档角色：`contract`

状态：`frozen`（T01 / Gate 1）

Owner：T01/T03

## 1. Active players

| 模式 | active player ids | 炮台 | HUD | 结果条件 |
|---|---|---|---|---|
| 单人 | `[1]` | P1 居中，P2 禁用/隐藏 | 仅 P1 | P1 第二次真正耗尽且 pending 为 0 |
| 双人 | `[1, 2]` | 原左右炮台 | P1/P2 | 两人第二次耗尽且全局 pending 为 0 |

所有循环必须使用 `config.get_active_player_ids()`，禁止在新增路径中继续硬编码 `[1, 2]`。仅为访问固定场景节点时可保留 P1/P2 映射，但逻辑必须过滤 inactive player。

## 2. `SessionState` 配置 API

| 方法/字段 | 类型 | 规则 |
|---|---|---|
| `configure(config)` | `GameSessionConfig -> bool` | 必须在 `_ready()` 启动单局前注入副本；合法时复制并返回 true |
| `config` | `GameSessionConfig` | 单局期间非空；操作切换只更新其 single control 字段 |
| `active_player_ids` | `Array[int]` | 从 config 派生，消费者获得副本 |
| `get_active_players()` | `Array[PlayerState]` | 稳定按 player_id 升序返回 |
| `is_player_active(id)` | `bool` | id 在 active ids 中 |

访问 inactive player：`get_player(2)` 在单人模式返回 null；UI、Audio、Spawn 和测试不得解引用 null。

`configure()` 为空、枚举非法、已经 `_ready()` 或单局已启动时返回 false 并保持原配置；缺少 active cannon 属于场景配置错误，开发运行中报错且不得开始生成。

## 3. 炮台配置

| 模式 | P1 位置 | P2 状态 | 初始角度 |
|---|---|---|---|
| 单人 | `(640, 670)`，随 stretch 保持底部中央 | hidden、process disabled、input disabled | `-90°` |
| 双人 | `(256, 670)` | `(1024, 670)`，启用 | 双方 `-90°` |

位置应由预定义布局锚点或模式配置方法设置，不在每帧重建节点。

## 4. 经济、保底与捕获

单人和双人的每个 active player 都使用同一 `PlayerState`：

| 项目 | 规则 |
|---|---|
| 初始金币 | 120 |
| 救援 | 第一次真正耗尽自动 +30，仅一次 |
| 第二次耗尽 | `is_exhausted = true`，停止该玩家输入 |
| 保底 | 有候选空网 3/5/7 次规则不变，按玩家独立 |
| 捕获公式 | 不变：`clamp(base × multiplier + pity, 0.01, 0.80)` |
| pending | 成功发射 +1，每发最终且仅 -1，不得为负 |

单人模式不存在 P2 经济、保底、统计或 pending；不得创建占位 PlayerState 参与结果判断。

## 5. 结果判断

通用算法：

```text
active_players 均 is_exhausted
AND active_players 的 pending_resolution_count 总和为 0
→ RESULTS
```

- 单人：P1 第二次真正耗尽后直接进入个人结果。
- 双人：保持双方耗尽后并列结果，不改变原行为。
- 结果状态停止生成与射击；切换操作方式不可离开 RESULTS。
- 个人结果展示捕获数、总价值、最大鱼，不出现“胜负”“伙伴等待”或 P2 空统计。

## 6. 捕获总数与 Boss

`SpawnDirector` 接收模式化阈值，不直接读取玩家数量：

| 项目 | 单人 | 双人 |
|---|---:|---:|
| 首次时间阈值 | 60s | 60s |
| 首次捕获数阈值 | 10 | 18 |
| 预告 | 2s | 2s |
| 冷却 | 90s | 90s |
| 场上 Boss 上限 | 1 | 1 |

`SpawnDirector.configure(first_boss_captures:int) -> bool` 只接受正整数，并必须在 `reset_session()` / 首次调度前调用。单人传 10、双人传 18；非法值返回 false，不覆盖上次合法值。

总捕获数为 active players 的 `capture_count` 之和。鱼类奖励、概率和普通鱼上限 20 不因模式改变。

## 7. 单局状态机

现有枚举保持：`RUNNING`、`PAUSED`、`RESULTS`。

新增约束：

1. 战斗实例创建并注入 config 后才允许进入 `RUNNING`。
2. `PAUSED` 时允许单人切换 control，但不允许修改 game mode。
3. 切换 control 不触发状态转换，不重置金币、保底或 Boss 时间。
4. 返回模式选择属于应用流，不是 `SessionState` 新状态。
5. `start_new_session()` 复用 config，重新创建 active PlayerState 并重置所有运行对象。

## 8. 音频与反馈

- 单人只使用 P1 射击音色/声像，不创建虚假的 P2 反馈。
- 单人耗尽文案进入结果，不显示“等待伙伴”。
- 双人救援、等待伙伴和并列结果文案保持现有行为。
- 模式选择时战斗 BGM 不播放；开始游戏后按原逻辑播放，Web 首次交互后恢复。

## 9. 回归不变量

以下旧行为必须保持：

1. 双人同时瞄准、换挡、点按/长按开火互不串线。
2. 同鱼原子声明、金币归属和一次奖励。
3. 3/5/7 保底边界和 Boss 不保证捕获。
4. 双人 120 初始、一次 30 救援、双方耗尽结算。
5. 鱼类、炮台资源字段和捕获数值不变。
6. Compatibility、Windows/Web 导出和 60 FPS 目标不变。

## 10. 失败模式

- active ids 与实际启用炮台不一致：Gate 2 失败。
- 单人创建 P2 PlayerState 或显示 P2 统计：Gate 2 失败。
- inactive P2 导致 null 解引用：自动测试失败，不使用静默替代。
- 返回选择后仍存在战斗节点或音频：生命周期测试失败。
- 模式化改造导致旧双人测试失败：先修回归，不放宽旧断言。
